# Проверка на реальных npm-пакетах

Дата проверки: 10 ноября 2026 года. Для каждого пакета выполнены наш анализатор с `--max-depth 10`, `npm view <имя> dependencies --json` и `npm ls --all` после установки во временную папку. В сравнительном сценарии npm запускается отдельно; основной анализатор читает JSON по HTTP и npm не вызывает.

| Пакет | Полученный порядок загрузки | Сравнение с npm |
| --- | --- | --- |
| is-number@7.0.0 | is-number@7.0.0 | Прямых зависимостей нет; npm подтверждает |
| is-odd@3.0.1 | is-number@6.0.0, is-odd@3.0.1 | Ребро и версии совпали |
| is-even@1.0.0 | is-buffer@1.1.6, kind-of@3.2.2, is-number@3.0.0, is-odd@0.1.2, is-even@1.0.0 | Все четыре ребра и версии совпали |

Для is-even получена цепочка: is-even@1.0.0 зависит от is-odd@0.1.2, тот от is-number@3.0.0, далее kind-of@3.2.2 и is-buffer@1.1.6. Загрузка в порядке, обратном этой цепочке, удовлетворяет зависимостям. Для этих трёх пакетов при глубине 10 различий в составе графа не обнаружено.

`npm ls` визуализирует установленное дерево, а наш инструмент выдаёт граф и допустимый топологический порядок. Фактический порядок выполнения установки npm этой командой не раскрывается, поэтому совпадение внутреннего расписания установки не утверждается. При меньшей глубине анализа часть транзитивных зависимостей намеренно пропускается. В других пакетах различия возможны из-за дедупликации npm, lockfile, дополнительных категорий зависимостей и документированного поднабора semver.

Воспроизведение:

```sh
./scripts/compare_with_npm.sh is-number
./scripts/compare_with_npm.sh is-odd
./scripts/compare_with_npm.sh is-even
```
